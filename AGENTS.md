# Project guidelines

Conventions for anyone changing this repository, people and AI tools alike.
CodeRabbit reads this file as review guidance.

## Layout

- `src/GuiRunner/TestCentric.Gui` – the WinForms GUI, organized as Model-View-Presenter:
  `Views` (forms and user controls, each behind an `I...View` interface),
  `Presenters`, `Dialogs`, `Controls`, `SettingsPages`, `Elements`.
- `src/GuiRunner/TestModel` – the model the presenters talk to (`ITestModel`), settings and projects.
- `src/GuiRunner/NUnit.UiException` – the stack trace and source code display.
- `src/GuiRunner/TestCentric.Exe` – the `testcentric.exe` entry point.
- `src/GuiRunner/*.Tests` – unit tests for the projects above.
- `src/TestData` – assemblies used as test inputs by unit and package tests. They contain
  deliberately failing, ignored or hanging tests; that is intended.
- `build.cake`, `package-tests.cake`, `KnownExtensions.cake` – the Cake build, which loads
  the shared `TestCentric.Cake.Recipe` package.

## Building and testing

- `dotnet tool restore`, then `dotnet cake --target=Build` or `dotnet cake --target=Test`.
  `build.ps1` / `build.cmd` are wrappers around the same thing.
- The GUI projects target .NET Framework 4.6.2 (`net462`) with C# 12. Code must compile
  against `net462`: APIs that exist only in .NET Core or .NET 5+ are not available.
- Nullable reference types are enabled and warnings are errors.
- Package versions are managed centrally in `Directory.Packages.props`.

## Code

- Follow `.editorconfig`: four spaces, Allman braces, `System.*` usings first.
- Every C# file starts with the copyright header used in the existing files.
- Presenters receive their view and the model through interfaces (`I...View`, `ITestModel`),
  so that they can be tested with substitutes and without showing any UI. Keep new logic in
  presenters or the model rather than in views.
- `*.Designer.cs` files are generated by the WinForms designer. Edit them through the designer
  or keep hand edits to what the designer would produce; logic belongs in the code-behind file.

## Tests

- NUnit 4 with NSubstitute. Test projects are NUnitLite executables.
- Presenter tests substitute the view and model interfaces and assert on calls received;
  new presenter behavior should come with such a test.
- Prefer `Assert.That` with constraints, as in the existing tests.

## Pull requests

- Work on a branch named `issue-NNNN` after the GitHub issue, and reference the issue in the PR.
- Labels and milestones are set by team members, not by agents. An issue gets its label when
  it is created, and is added to the next release's milestone when its PR is approved.
- Every closed issue in a milestone needs one of the labels under `issue-labels-include` or
  `issue-labels-exclude` in `GitReleaseManager.yaml`, or the release notes fail to build.
  Included labels, Build among them, appear in the release notes; excluded ones, such as
  Refactor, do not.
- One human review is expected before merging.
